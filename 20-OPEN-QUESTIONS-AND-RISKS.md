# Open Questions and Risks

## Fundamental
- Does the systems-level gap actually exist?
- Is this a discipline, methodology, integration framework or product architecture?
- Which parts are already covered by emerging standards?
- Is a root manifest genuinely useful or unnecessary indirection?

## Model interaction
- Will LLMs reliably understand the contract?
- How much schema/context is too much?
- Does structured control reduce model performance?
- Which fields should be loaded progressively?
- How model-sensitive is the format?

## Economics
- What control-plane tax is acceptable?
- When does independent verification pay for itself?
- Can cheaper models outperform expensive models under better system control?
- How should human attention be priced?

## UX
- Will users understand “mission”?
- Is chat, GUI or hybrid best by task/person?
- How much status is useful vs distracting?
- How should trust calibration be measured longitudinally?
- Does “Needs You” reduce interruption without hiding risk?

## State/distributed systems
- What consistency level is required?
- How should stale state be represented?
- How are multi-agent conflicts resolved?
- What is the canonical event model?

## Authority
- How much belongs in ISE vs AIE?
- How are delegation proofs represented portably?
- How should runtime policy engines map into the contract?

## Assurance
- What counts as independent verification?
- How should evidence strength be ranked?
- How is evidence minimized for privacy?
- What is the correct semantic-compliance benchmark?

## Standards
- What is core vs extension?
- Which namespaces and discovery mechanisms should be reused?
- How are breaking changes managed?
- What conformance profiles are actually valuable?

## IP
- Which mechanisms may be patentable?
- Which are obvious combinations of prior art?
- What must stay private until patent review?

## Kill risks
- no measurable reliability gain
- unacceptable latency/cost overhead
- lower model performance due to complexity
- no meaningful portability benefit
- poor user preference/retention
- strong equivalent prior art
- existing standards close the identified gap before the work matures
