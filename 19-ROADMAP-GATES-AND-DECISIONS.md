# Roadmap, Gates and Decisions

## Phase A — Prove the problem
- STUDY-001 discipline/standards map
- prior-art registry
- source-code archaeology
- product/black-box reconnaissance
- user/market evidence
- identify measurable gap

Gate: D1 / D2 / D3.

## Phase B — Minimal formalization
- core terminology
- mission contract v0.1
- principal/authority model
- state/lifecycle
- capability object
- assurance/evidence model
- complexity budget

Gate: internal coherence and implementability.

## Phase C — Human-first prototype
- goal-first onboarding
- mission preview
- NOW / Needs You
- progress
- cost/risk visibility
- pause/takeover
- evidence summary
- progressive disclosure

Gate: usability and comprehension.

## Phase D — Runtime v0.1
- manifest loader
- mission parser
- state store
- capability resolver
- policy hooks
- trajectory recorder
- assurance engine
- evidence store
- cost/performance telemetry

## Phase E — Multi-runtime adapters
At least three runtimes/frameworks.

Gate:
same semantic mission across runtimes.

## Phase F — Before/after experiments
Run ablations and failure injection.

Gate:
material benefit vs strong baseline.

## Phase G — Independent implementation
External team implements from spec.

Gate:
interop and conformance without handholding.

## Phase H — Adoption
Pilot with independent projects/organizations.

Measure:
integration reduction, CPVO, VSR, human effort, user retention.

## Phase I — Standardization candidate
Only after evidence:
public governance, v1 specification, conformance suite, formal standards mapping and external stakeholder coalition.
